既有 `AiTutorAskFlowTests.java` 只补新事务管理器、行锁查询的 Mock 夹具，没有删改原断言。这些 Mock 不被当作真实事务证据，事务结论来自隔离 MySQL。

## 浏览器完整流程（隔离环境）

使用本轮新建的虚构班级和学生，通过页面真实执行：

1. 教师新建并发布任务。
2. 学生填写完成说明和解决过程，通过文件选择器上传测试 PNG，保存草稿；刷新和退出重新登录后文字与选中截图一致，尚无正式版本。
3. 学生正式提交第一版。教师查看并退回，评语要求补充错误处理。
4. 学生保留原截图，修改说明后提交第二版。
5. 教师给第二版 **93 分**。学生重新登录、刷新后看到最新分数和第一版退回意见。
6. 数据库只读复核：2 个不可变版本，评价顺序 REVISE / PASS(93)，同一真实磁盘截图有两条版本关联。

其他浏览器验证：

- 任务入口带正确项目和任务进入 AI；本地桩 401 显示可理解提示且没有登出。
- 本地桩恶意 HTML 回答确实进入页面，安全文本可见；DOM 无 script、事件属性或 javascript 链接，脚本哨兵未执行。
- 切换报修进入新会话草稿，可新建报修会话；恢复旧抢票会话时任务与回答正确恢复。
- 对隔离后端做有界暂停，任务请求超时后显示「任务列表加载失败，请重试」；自动恢复后重试成功，任务下拉恢复可用。
- 390px 下学生成果和 AI 页无页面横向溢出，导航允许自身横向滚动；实际点击、输入、切换均完成。
- 末次浏览器 error/warn 日志为空，流程未观察到未处理脚本异常。协议桩 HTML、错误均不是实际模型成功回答。

## 测试失败与测试程序纠正

原始失败日志留在项目外私有工作目录，不上传原始响应或数据库内容。

- 首轮除了 F1/F2，还遇到测试自身错误：MySQL CLI 复合触发器缺分隔符、读取 `refs` 而实际契约字段为 `contextRefs`，以及 SQL 子进程管道未关闭。均在测试程序中修正。
- 第二轮明确触发 F3；引用断言还错误要求文档路径/任务 ID 必须逐字出现于模型正文。现按业务契约核对实际任务内容、实际存在的源文件及其贡献的 operationId；在未重新加载业务修复时，该纠正后的引用测试已独立通过。
- 最后一次只读截图证据查询误用不存在的 `task_id` 列，改为通过 `attachment_id` 关联核对；无写入、无业务修复。
- 浏览器自动化一次等待超时提示的等待窗口短于前端真实 30 秒超时；没有因此改动应用超时，后续观察到真实错误态并完成重试验证。
- 没有跳过用例、放宽业务失败断言或更改限额/评分/提交规则以获得通过。
