## 2. 环境准备

虚拟机原本没有 Java、Maven、MySQL。由于没有 sudo 权限，全部依赖以「解压到用户目录」的方式准备。

| 组件 | 版本 | 获取方式 | 位置 |
| --- | --- | --- | --- |
| JDK | Temurin 21.0.12.1+1 | 清华 TUNA 镜像（Adoptium） | `~/tools/opt/jdk-21.0.12.1+1` |
| Maven | 3.9.16 | 清华 TUNA 镜像（Apache） | `~/tools/opt/apache-maven-3.9.16` |
| MySQL | 8.0.44（linux-glibc2.17-x86_64） | 官方 CDN | `~/tools/opt/mysql-8.0.44-...` |
| libaio | 0.3.113（libaio1t64 解包） | Ubuntu 源 `apt-get download` | `~/tools/opt/lib`（提供 `libaio.so.1`） |
| Node.js | v24.14.0（系统已有，nvm 安装） | — | — |
| 浏览器 | Google Chrome（系统已有） | — | `/opt/google/chrome/chrome` |

遇到的问题与处理：

1. **代理速度过慢**：最初从 `api.adoptium.net` 下载 JDK 只有约 30 KB/s。
   经检查使用了 HTTP 代理，改为直连国内镜像后正常，**没有猜测或改写代理地址**。
2. **MariaDB 与 Hibernate 7 不兼容**：先尝试 MariaDB 11.4.13，
   启动时报 `Unknown column 'RESERVED' in 'WHERE'`，导致无法读取数据库元数据、无法确定方言。
   为与参考项目保持一致（项目使用 `mysql-connector-j` 连接 MySQL），
   改用真正的 MySQL 8.0.44。
3. **`mariadbd` / `mysqld` 缺少 `libaio.so.1`**：Ubuntu 24.04 提供的是 `libaio.so.1t64`。
   通过 `apt-get download libaio1t64` + `dpkg-deb -x` 解包到用户目录，并建立符号链接解决。
4. **MySQL 客户端缺少 `libncurses.so.5`**：同样用符号链接指向系统 `libncurses.so.6`。
5. **误杀自身 shell**：早期用 `pkill -f mariadbd` 时匹配到了自己的命令行导致 shell 被终止。
   改为按 pid 文件精确停止。

## 4. 后端复现

按模块推进，每个模块完成后编译：

1. `common` / `config` / `exception`：统一响应、跨域、拦截器注册、全局异常。
2. `entity`（15 个）：与参考项目的表名、列名、类型、长度逐项对应。
3. `dto` / `vo`（19 个）：请求与响应载体，字段名保持兼容。
4. `mapper`（15 个）：MyBatis-Plus `BaseMapper`，另加工作空间行锁查询。
5. `util`（7 个）：口令散列、凭证、Excel 解析、富文本清洗、图片存取、基准数据。
6. `interceptor`（2 个）：登录校验与权限边界、访问码与空间解析。
7. `service` / `service/impl`（11 + 12 个）：全部业务规则。
8. `controller`（6 个）：67 个接口，负责把内部状态码翻译成 HTTP 状态码。

**编译问题与修复**

| 问题 | 现象 | 根因 | 修复 |
| --- | --- | --- | --- |
| `Resource` 名称冲突 | 编译报 `reference to Resource is ambiguous`，并连带出现 60 余条「找不到 Lombok 访问器」 | `RepairController` 同时导入了 `jakarta.annotation.Resource` 与 `org.springframework.core.io.Resource`；该错误让注解处理阶段被跳过，导致 Lombok 未生成方法 | 只导入 jakarta 的 `Resource`，Spring 的用全限定名 |
| 注解处理依赖环境 | 修复上述冲突后即可编译，但为保证可复现 | JDK 21 起注解处理默认行为有变化 | 在 `maven-compiler-plugin` 中显式声明 `<proc>full</proc>` |
| 工作空间初始化路径 | 生成的路径为 `/api/sys-workspaceclasses/...` | `@PostMapping("classes/...")` 缺少前导斜杠 | 改为 `@PostMapping("/classes/...")` |

最终：`mvn clean compile` → 97 个源文件、BUILD SUCCESS、0 错误。

### 7.3 验证过程中修正的问题

验证脚本本身也经过多轮修正，这些修正过程同样记录在此，避免把「测试写错」误当成「实现有错」：

| 现象 | 根因 | 处理 |
| --- | --- | --- |
| 大量断言误报 401 | 验证脚本把「响应体 + 状态码」拼成多行文本再用 `tail -n 1` 取状态码，单行 JSON 被截断，导致后续变量为空 | 改为响应体与状态码分别保存在变量 / 文件中 |
| 出现重复的辅助函数定义 | 多次修补脚本时叠加了同名函数，后定义的旧版本生效 | 去重并只保留一份定义 |
| 报名接口报 409「报名尚未开始」 | 测试用 `status=1` 选取活动，命中了「已发布但报名未开始」的活动 | 改为同时校验报名时间窗口与剩余名额 |
| 报名接口报 404「模拟用户不存在」 | shell 变量名使用了只读的 `UID`，赋值失败导致 ID 为空 | 重命名变量 |
| 「未知项目路径」期望 404 实得 401 | 访问码校验先于路由匹配执行，非法路径同样会先被鉴权拒绝 | 断言改为接受 401 或 404，并说明原因 |
| 「已发布活动不能回到草稿」期望 409 实得 400 | 目标状态 0 先被参数校验拦下 | 断言改为 400，并补充已关闭活动不可修改的 409 断言 |
| 「非参与师傅」期望空列表实得 1 条 | 改派会在处理记录中写入 `target_user_id`，被改派过的师傅也属于「曾参与」 | 修正断言，分别验证 ASSIGNED 与 PARTICIPATED 两种范围 |
| 重置后查询票券 / 工单返回 `NO_DATA` | 重置会重建模拟用户，数据库主键随之变化，旧 ID 失效 | 重置后重新查询模拟用户 ID 再断言 |
| 上传图片报「图片内容损坏」 | 测试素材 PNG 的 IDAT 压缩数据在生成时经过了字符串转换而被破坏 | 重写素材生成脚本，二进制数据用 `Buffer` 拼接 |
| 浏览器渲染进程崩溃 | 虚拟机可用内存约 1.3 GB，整页截图与 `page.reload()` 峰值过高 | 收敛 Chrome 参数、截图改为尽力而为、用新页面替代整页刷新 |

## 9. 第二轮审查与修复

第二轮审查聚焦并发正确性、启停脚本安全性、数据库初始化安全性、隔离验证脚本的
证据有效性与文档准确性。完整的问题—修复—验证记录见
[docs/06-review-fixes.md](06-review-fixes.md)。

要点：

* 修复同一账号首次并发登录的唯一记录竞争与访问码覆盖问题（账号行加锁 + 加锁读 + 单条 upsert）；
* 启停脚本改为生命周期单锁、严格服务身份判定、完整就绪校验与精确停止；
* `init-db.sh` 改为「只做首次新建」，库或账号已存在即拒绝，移除删除入口；
* 回归脚本改为只读身份核验、失败即停、凭证不落输出、私有临时目录；
* 期间曾尝试用 H2 为并发写入补单元测试，因「子线程各自持锁、无法验证真实服务」且引入
  额外依赖，已连同 H2 依赖与测试配置一并移除；后端单元测试保持原有的 9 个纯逻辑用例。

本节所记录的修复均在本轮实际执行过对应验证；未执行的部分在
`docs/06-review-fixes.md` 第 5 节「未验证 / 未执行」中单独列出。
